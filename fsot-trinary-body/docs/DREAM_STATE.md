# Dream state — FSOT connective sleep (not defrag)

## Your idea, formalized

Sleep is not “run DEFRAG while offline.”  
Sleep includes a **dream phase**: the body **self-organizes** memory into patterns that already make sense under **FSOT**.

| Op | When | What |
|----|------|------|
| **SAVE** | Checkpoint | Snapshot working set → disk. **No dream.** |
| **SLEEP** | Consolidation | Plastic rest → **DREAM (FSOT weave)** → LTM snapshot |
| **DEFRAG** | Waking, explicit | Core-safe compact/dedupe. **Not** the dream. |
| **APPEND** | Anytime | Episodic line; does not clobber `core:` |

## How the dream weaves (FSOT)

1. **Harvest** traces from home/knowledge, genome, tools, proposals, identity sessions, notes.  
2. **Classify** each line: domain (quantum/bio/cosmo/code/self/…) + soft **emergence/damping sign**.  
3. **Connect** pairs by:
   - same domain  
   - same FSOT sign (cohere)  
   - weak bridges across opposite signs  
   - genome guidance (`δψ`, `d_eff`, `emergence_preference`, domain coupling)  
   - organ Trit weight (express weighs more than repress)  
4. **Cluster** greedily by connectivity (highest-weight seeds first).  
5. **Write weave** into `/home/knowledge` as `cluster:N domain=… polarity=emergence|damping`.  
6. **Session note** on identity: `session: dream t=… clusters=…` (append only).  
7. **Journal** into notes organ for telemetry.

`core:` identity lines keep high weight and are never “dreamed away.”
